## Introduction

“What would change my mind?” is a small question with a large effect: it turns a conclusion from something you defend into something you can test. In practical thinking, the point is not to become endlessly doubtful or to abandon convictions at the first objection. It is to name, in advance, the evidence, observation, result, or failed prediction that would make you revise your view. That protects you from reasoning that cannot lose.


<img src="{{ "/assets/images/improving_your_think_da4710_change_my_mind_f0f53e-overview.webp" | relative_url }}" alt="Overview image for Change Mind" loading="eager" decoding="sync" fetchpriority="high">
This question matters because people naturally search for, notice, and trust evidence that fits what they already believe. Psychologists call this confirmation bias: the tendency to give more weight to belief-consistent information and less weight to evidence that challenges it. A “change my mind” question interrupts that pattern by forcing the decision-maker to specify what would count against the current conclusion, not only what would support it.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://thedecisionlab.com/biases/confirmation-bias" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: thedecisionlab.com">[The Decision Lab]</a><span class="citation-popover" role="note"><span class="citation-popover-source">thedecisionlab.com</span><span class="citation-popover-snippet">The Decision LabConfirmation BiasConfirmation bias describes our underlying tendency to notice, focus on, and provide greater credence to...</span></span></span>

Used well, it becomes a practical intervention for better judgement: define the claim, identify [disconfirming evidence]({{ 'disconfirming-evidence/' | relative_url }}), set [review triggers]({{ 'review-triggers/' | relative_url }}), and make belief revision feel like progress rather than defeat.

## Why this question improves thinking

The question works because it changes the structure of the reasoning task. Instead of asking, “Can I find reasons I am right?”, it asks, “What would I expect to see if I were wrong?” That is a different cognitive move.

Peter Wason’s classic 2-4-6 rule-discovery experiment illustrates the problem. Participants were shown the sequence 2, 4, 6 and asked to discover the rule by proposing other number triples. Many tested examples that fitted their first guess, such as more even numbers increasing by two, rather than examples that could disprove it. The actual rule was broader: ascending numbers. Wason interpreted the pattern as a preference for confirmation over falsification.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://bear.warrington.ufl.edu/brenner/mar7588/Papers/wason-qjep1960.pdf" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: bear.warrington.ufl.edu">[bear.warrington.ufl.edu]</a><span class="citation-popover" role="note"><span class="citation-popover-source">bear.warrington.ufl.edu</span><span class="citation-popover-title">On the failure to eliminate hypotheses in a conceptual task</span><span class="citation-popover-snippet">On the failure to eliminate hypotheses in a conceptual task</span></span></span>

The lesson is not that people are foolish. It is that a confirming test often feels informative even when it is weak. If you believe a project is on track, asking team members to list reasons it might succeed will probably produce plausible answers. Asking what evidence would show it is not on track is more useful: missed milestones, rising defect rates, user drop-off, unresolved dependencies, budget burn, or repeated “temporary” workarounds.

In this sense, “What would change my mind?” is a testability device. It pushes a belief towards the same discipline that makes a scientific claim useful: a claim should forbid something, or at least expose itself to possible contradiction. Philosophers and scientists debate the limits of falsifiability as a full theory of knowledge, but the everyday version remains valuable: a view that cannot name any possible contrary evidence is not being seriously tested.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://en.wikipedia.org/wiki/Falsifiability" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: Wikipedia">[Wikipedia]</a><span class="citation-popover" role="note"><span class="citation-popover-source">Wikipedia</span><span class="citation-popover-snippet">Open source on wikipedia.org.</span></span></span>

## Turn conclusions into testable claims

The first implementation step is to translate a broad judgement into a claim that could be checked. “This strategy is good” is too vague. “This strategy will reduce customer churn among small-business users within two quarters without raising support costs” is much easier to test.

A useful change-my-mind question usually has [three parts]({{ 'three-parts/' | relative_url }}):


<div class="content-enhancement content-enhancement--decision" markdown="1">

* **Current conclusion:** What do I currently believe or plan to do?
* **Decision-relevant assumption:** What must be true for that conclusion to hold?
* **Revision condition:** What evidence would make me lower confidence, change course, or stop?

</div>

For example, a team might believe: “We should launch the new onboarding flow to all users.” The change-my-mind version would be: “What evidence would make us delay or narrow the launch?” Good answers might include a statistically meaningful fall in activation among new users, a spike in support tickets from a specific segment, poor performance on mobile, or failed accessibility checks.

This is stronger than a general instruction to “be open-minded”. Research on [actively open-minded]({{ 'open-mindedness/' | relative_url }}) thinking defines it in behavioural terms: considering alternative opinions, being sensitive to contradictory evidence, delaying [premature closure]({{ 'premature-closure/' | relative_url }}), and recognising that one’s judgement can be wrong. The practical question gives those ideals a place to operate inside a real decision.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://pmc.ncbi.nlm.nih.gov/articles/PMC9966223/" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: pmc.ncbi.nlm.nih.gov">[PMC]</a><span class="citation-popover" role="note"><span class="citation-popover-source">pmc.ncbi.nlm.nih.gov</span><span class="citation-popover-title">PMCActively Open-Minded Thinking and Its Measurement</span><span class="citation-popover-snippet">PMCActively Open-Minded Thinking and Its Measurement</span></span></span>

The most important design rule is specificity. A trigger such as “if the data looks bad” leaves too much room for motivated interpretation. A trigger such as “if week-four retention falls by more than five percentage points for the treatment group, or if support tickets rise by more than 15 per cent for two consecutive weeks” is harder to explain away after the fact.

## Look for disconfirming evidence, not just more evidence

More information does not automatically improve judgement. If the search is biased, more information may simply give a person more material with which to defend their existing position. That is why the question should be aimed at disconfirming evidence: the kind of finding that would make the current view less likely, not merely less comfortable.

Disconfirming evidence can take several forms:

* **A failed prediction:** “We expected referrals to rise after the campaign, but they did not.”
* **A missing mechanism:** “The proposed cause does not appear in the cases where it should appear.”
* **A counterexample:** “The policy works in one group but fails in the group it was mainly meant to help.”
* **A better [rival explanation]({{ 'rival-test/' | relative_url }}):** “The outcome can be explained by seasonality, not by our intervention.”
* **A revealed trade-off:** “The plan improves speed but damages quality enough to erase the benefit.”

The value of disconfirming evidence is clear in forecasting research. Studies of expert forecasting and the Good Judgment Project found that better forecasters update their beliefs more often as evidence changes, and that actively open-minded thinking is among the traits associated with better performance. The key habit is not dramatic reversal; it is incremental updating when the world gives new information.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://stanford.edu/~knutson/jdm/mellers15.pdf" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: stanford.edu">[Stanford University]</a><span class="citation-popover" role="note"><span class="citation-popover-source">stanford.edu</span><span class="citation-popover-snippet">Open source on stanford.edu.</span></span></span>

That distinction matters. Changing your mind does not have to mean flipping from “yes” to “no”. It can mean moving from 80 per cent confidence to 60 per cent, narrowing the scope of a claim, postponing a decision, running a smaller trial, or replacing one explanation with a better one. A good change-my-mind question allows partial revision.

## Use the question before the decision hardens

The best time to ask “What would change my mind?” is before social, financial, or identity commitments make revision painful. Once a public position has been taken, a budget has been approved, or a team has invested months of effort, contrary evidence becomes easier to reinterpret as noise.

This is why the question pairs well with a premortem. Gary Klein’s premortem method asks a team to imagine that a project has already failed and then work backwards to explain why. Klein argued that this makes it safer for knowledgeable dissenters to voice concerns during planning, when those concerns can still change the plan.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://hbr.org/2007/09/performing-a-project-premortem" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: hbr.org">[Harvard Business Review]</a><span class="citation-popover" role="note"><span class="citation-popover-source">hbr.org</span><span class="citation-popover-title">Harvard Business Review Performing a Project Premortem</span><span class="citation-popover-snippet">Harvard Business Review Performing a Project Premortem</span></span></span>

A change-my-mind version of a premortem is especially practical:


<div class="content-enhancement content-enhancement--step-flow" markdown="1">

1. Assume the decision has failed.
2. List the earliest signs that failure was becoming likely.
3. Convert those signs into review triggers.
4. Decide in advance what action each trigger will cause.

</div>

For a hiring decision, a trigger might be: “If the work-sample test contradicts the interview impression, we will give the work sample more weight.” For a product launch, it might be: “If early adopters use the feature once but do not return, we will treat excitement as curiosity rather than demand.” For a policy intervention, it might be: “If the programme helps the easiest-to-reach group but not the target group, we will redesign the delivery model rather than declare success.”

This turns dissent from a personality conflict into a planning tool. The question is no longer “Who is being negative?” but “Which evidence would tell us that our assumptions are failing?”

## Decision review triggers make revision easier

A review trigger is a pre-agreed condition that reopens a decision. It protects a team from two common errors: changing course too quickly because of random noise, and refusing to change course because the original decision has become emotionally or politically costly.

Good triggers are observable, timely, and connected to the reason for the decision. They should not be so sensitive that every fluctuation causes panic, nor so vague that nothing ever qualifies.

A strong trigger usually specifies:


<div class="content-enhancement content-enhancement--decision" markdown="1">

* **Metric or observation:** What exactly will be watched?
* **Threshold:** How much change is enough to matter?
* **Time window:** Over what period must the evidence appear?
* **Action:** What happens if the trigger is met?
* **Owner:** Who is responsible for calling the review?

</div>

For example: “If the pilot does not reach at least 70 per cent completion among eligible participants after eight weeks, the team will pause expansion and review recruitment, user burden, and eligibility rules.” That is a decision review trigger. It does not require panic. It requires attention.

This approach also improves group decision-making because it separates two conversations that are often confused. The first conversation is about what to do now. The second is about what would make the group reconsider. A team can commit to action while still admitting uncertainty.

## What a good answer sounds like

A useful answer to “What would change your mind?” is concrete enough that another person could recognise the evidence when it appears. It does not have to be perfectly quantified, but it should reduce wiggle room.

Weak answers include:


<div class="content-enhancement content-enhancement--insight-grid" markdown="1">

* “I would change my mind if the evidence were convincing.”
* “I would change my mind if things got worse.”
* “I would change my mind if experts disagreed.”
* “I would change my mind if the plan clearly failed.”

</div>

These sound open-minded but are too elastic. They allow the person to move the standard later.

Stronger answers include:

* “I would change my mind if two independent datasets showed the effect disappearing after controlling for age and income.”
* “I would change my mind if the pilot improved satisfaction but did not improve repeat usage after one month.”
* “I would change my mind if the strongest alternative explanation predicted the result more accurately than my explanation.”
* “I would change my mind if people who disagree with me could forecast the next three [outcomes]({{ 'outcomes/' | relative_url }}) better than I can.”

The last example is particularly useful in messy real-world disagreements. When evidence is complex, prediction can reveal which model is actually doing work. LessWrong’s discussion norms often encourage people to make concrete models, state predictions, and note what would change their minds; the useful part of that practice is that it moves disagreement from identity and rhetoric towards decision boundaries.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://www.lesswrong.com/posts/MqrzczdGhQCRePgqN/feedback-requested-draft-of-a-new-about-welcome-page-for" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: lesswrong.com">[LessWrong]</a><span class="citation-popover" role="note"><span class="citation-popover-source">lesswrong.com</span><span class="citation-popover-snippet">Open source on lesswrong.com.</span></span></span>

## When the question fails

The question is powerful, but it can be misused. Sometimes people answer it in a way that only pretends to be testable.

One failure mode is the **impossible standard**: “I would change my mind if there were absolute proof.” In most real decisions, absolute proof is unavailable. The better standard is proportionate evidence: enough to change confidence or action given the stakes.

Another failure mode is the **moving target**. A person names a condition, the condition occurs, and then they explain why it does not count. This is why it helps to write the condition down before the result is known.

A third failure mode is **isolated fact-checking without model revision**. Someone concedes one detail but protects the broader conclusion from any possible damage. Sometimes that is reasonable; one error need not destroy a whole view. But if every failed prediction is treated as irrelevant, the view is not being updated.

A fourth failure mode is **performative open-mindedness**. In public debate, “what would change your mind?” can become a challenge meant to embarrass the other person. Used that way, it may produce defensiveness rather than reflection. Evidence from persuasion and belief-change research suggests that people often resist facts that threaten identity, group belonging, or prior commitment; better thinking therefore depends not only on evidence quality, but also on whether the setting makes revision psychologically safe.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://www.newyorker.com/magazine/2017/02/27/why-facts-dont-change-our-minds" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: newyorker.com">[The New Yorker]</a><span class="citation-popover" role="note"><span class="citation-popover-source">newyorker.com</span><span class="citation-popover-title">The New Yorker Why Facts Don&#x27;t Change Our Minds</span><span class="citation-popover-snippet">Cognitive biases, especially confirmation bias (termed &quot;myside bias&quot; by Mercier and Sperber), lead people to embrace information that sup...</span></span></span>

The remedy is to use the question first on yourself. “What would change my mind?” is more credible when it is not only demanded of opponents.

## A practical script for better decisions

The easiest way to use the question is to add it to any decision memo, meeting agenda, personal journal, or project review. It works best when it is written before the evidence arrives.

A compact decision script looks like this:

**1. State the conclusion.**

“We should proceed with the pilot.”

**2. Name the core assumptions.**

“This will work if the target users understand the offer, find the process easy enough, and receive the promised benefit quickly.”

**3. Ask the change-my-mind question.**

“What evidence would make us stop, redesign, or narrow the pilot?”

**4. Define disconfirming signals.**

“Low completion, repeated confusion at the same step, no measurable improvement for the intended group, or high delivery cost per successful case.”

**5. Set review triggers.**

“At week four and week eight, review completion, cost, user feedback, and outcome data. Pause expansion if two or more [red flags]({{ 'red-flags/' | relative_url }}) cross the agreed thresholds.”

**6. Pre-commit to the response.**

“If the trigger is met, we will not explain it away as early noise until we have checked the assumption it challenges.”

This script is deliberately plain. Its value is not sophistication; it is that it makes reasoning visible. Once the revision conditions are visible, other people can challenge them, improve them, and hold the decision to them.

## The deeper habit: make beliefs easier to update

The deepest benefit of “What would change my mind?” is cultural. It treats belief revision as a normal part of good judgement rather than a humiliating admission of failure. That matters in organisations, politics, science, personal decisions, and everyday disagreements.

A person who can answer the question well is doing several things at once: separating identity from belief, exposing assumptions, inviting contrary evidence, and building a bridge between confidence and humility. Research on actively open-minded thinking supports this general pattern: better reasoning is linked not to having no beliefs, but to being willing to seek and weigh evidence that may count against them.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://pmc.ncbi.nlm.nih.gov/articles/PMC9966223/" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: pmc.ncbi.nlm.nih.gov">[PMC]</a><span class="citation-popover" role="note"><span class="citation-popover-source">pmc.ncbi.nlm.nih.gov</span><span class="citation-popover-title">PMCActively Open-Minded Thinking and Its Measurement</span><span class="citation-popover-snippet">PMCActively Open-Minded Thinking and Its Measurement</span></span></span>

The practical standard is simple: before defending a conclusion, ask what would make it weaker. Before expanding a policy, ask what would show it is failing. Before trusting a story, ask what observation would surprise it. Before arguing harder, ask whether the disagreement has a test.

A conclusion that can survive that treatment is stronger. A conclusion that cannot may still be emotionally satisfying, but it is no longer doing the work of careful thought.

    if (select) {
      return Array.prototype.slice.call(select.options)
        .map(function (option) { return option.value; })
        .filter(function (marketId) { return !!markets[marketId]; });
    }
    return Array.prototype.slice.call(section.querySelectorAll('[data-ebay-market-button]'))
      .map(function (button) { return button.getAttribute('data-ebay-market-button'); })
      .filter(function (marketId) { return !!markets[marketId]; });
  }
  function applyMarket(section, marketId, persist) {
    var available = availableMarkets(section);
    if (available.indexOf(marketId)< 0) marketId = available[0] || defaultMarket;
    Array.prototype.slice.call(section.querySelectorAll('[data-ebay-localized-link]')).forEach(function (link) {
      var query = link.getAttribute('data-ebay-query') || '';
      var reference = link.getAttribute('data-ebay-reference') || '';
      link.setAttribute('href', buildUrl(query, reference, marketId));
    });
    var select = section.querySelector('[data-ebay-market-select]');
    if (select && available.indexOf(marketId) >= 0) select.value = marketId;
    var selectedText = marketId;
    if (select && select.selectedIndex >= 0) selectedText = select.options[select.selectedIndex].text;
    Array.prototype.slice.call(section.querySelectorAll('[data-ebay-selected-market-label]')).forEach(function (label) {
      label.textContent = selectedText;
    });
    Array.prototype.slice.call(section.querySelectorAll('[data-ebay-selected-market-flag], [data-ebay-trigger-market-flag]')).forEach(function (flag) {
      flag.className = flagClass(marketId);
    });
    Array.prototype.slice.call(section.querySelectorAll('[data-ebay-trigger-market-label]')).forEach(function (label) {
      label.textContent = selectedText;
    });
    Array.prototype.slice.call(section.querySelectorAll('[data-ebay-domain-label]')).forEach(function (label) {
      label.textContent = domainLabel(marketId);
    });
    Array.prototype.slice.call(section.querySelectorAll('[data-ebay-market-option]')).forEach(function (button) {
      button.setAttribute('aria-selected', button.getAttribute('data-ebay-market-option') === marketId ? 'true' : 'false');
    });
    Array.prototype.slice.call(section.querySelectorAll('[data-ebay-market-button]')).forEach(function (button) {
      var active = button.getAttribute('data-ebay-market-button') === marketId;
      button.setAttribute('aria-pressed', active ? 'true' : 'false');
    });
    section.setAttribute('data-ebay-selected-market', marketId);
    if (persist) {
      try { if (window.localStorage) localStorage.setItem('phoenix-ebay-market', marketId); } catch (err) {}
    }
    closeMenu(section);
  }
  sections.forEach(function (section) {
    if (section.getAttribute('data-ebay-localized-init') === '1') return;
    section.setAttribute('data-ebay-localized-init', '1');
    var available = availableMarkets(section);
    var marketId = defaultMarket;
    if (window.PhoenixAffiliateLocation && window.PhoenixAffiliateLocation.inferMarket) {
      marketId = window.PhoenixAffiliateLocation.inferMarket(available, {
        storageKey: 'phoenix-ebay-market',
        defaultMarket: defaultMarket
      });
    } else if (available.indexOf(defaultMarket)< 0) {
      marketId = available[0] || defaultMarket;
    }
    var select = section.querySelector('[data-ebay-market-select]');
    if (select) {
      select.addEventListener('change', function () {
        applyMarket(section, select.value, true);
      });
    }
    var trigger = section.querySelector('[data-ebay-market-trigger]');
    var menu = section.querySelector('[data-ebay-market-menu]');
    if (trigger && menu) {
      trigger.addEventListener('click', function (event) {
        event.stopPropagation();
        var expanded = trigger.getAttribute('aria-expanded') === 'true';
        menu.hidden = expanded;
        trigger.setAttribute('aria-expanded', expanded ? 'false' : 'true');
        var picker = trigger.closest('.fr-ebay-market-picker');
        if (picker) picker.classList.toggle('fr-ebay-market-picker--open', !expanded);
      });
      Array.prototype.slice.call(menu.querySelectorAll('[data-ebay-market-option]')).forEach(function (button) {
        button.addEventListener('click', function (event) {
          event.stopPropagation();
          applyMarket(section, button.getAttribute('data-ebay-market-option'), true);
        });
      });
      document.addEventListener('click', function () { closeMenu(section); });
    }
    Array.prototype.slice.call(section.querySelectorAll('[data-ebay-market-button]')).forEach(function (button) {
      button.addEventListener('click', function () {
        applyMarket(section, button.getAttribute('data-ebay-market-button'), true);
      });
    });
    applyMarket(section, marketId, false);
  });
})();
